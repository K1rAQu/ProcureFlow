# 📦 ProcureFlow — Система керування закупівлями підприємства

Сучасна внутрішня веб-система підприємства для формування, погодження, маршрутизації та виконання заявок на закупівлю комплектуючих, матеріалів та обладнання з єдиним довідником номенклатури.

**Технологічний стек:**
* **Платформа:** Next.js 16 (App Router, React 19, Server Components) + TypeScript
* **База даних:** Вбудована SQLite (LibSQL) + Drizzle ORM (параметризовані запити, захист від SQLi)
* **Стилі:** Tailwind CSS 4
* **Безпека:** Захищені `HttpOnly` сесії, Google OAuth 2.0, повне блокування індексації роботами (`noindex`), гнучке геоблокування та VPN-фільтр.

---

## 🚀 1. Швидкий запуск

Система не потребує встановлення сторонніх серверів баз даних (PostgreSQL/MySQL) — база даних зберігається локально в SQLite-файлі (`./data/procurement.db`) та автоматично створює всі таблиці й початкові довідники при першому запуску.

### Вимоги:
* Node.js версії 20.x або новішої.

### Запуск на Windows:
Двічі клацніть файл:
```cmd
start.bat
```
або через PowerShell:
```powershell
.\start.ps1
```

### Ручний запуск у консолі:
```bash
npm install
npm run dev
```

Відкрийте в браузері: [http://localhost:3000](http://localhost:3000)

## ⚙️ 3. Налаштування середовища (`.env`)

Скопіюйте файл `.env.example` у `.env` та за потреби вкажіть параметри:

```env
# База даних та файли
DATABASE_URL=file:./data/procurement.db
UPLOAD_DIR=./var/uploads
APP_URL=http://localhost:3000

# Google OAuth (Вхід та реєстрація)
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=

# Обмеження реєстрації за єдиним корпоративним доменом пошти (наприклад: company.ua)
# Дозволяє вхід виключно співробітникам компанії. Не розкривається у клієнтському коді.
CORPORATE_EMAIL_DOMAIN=

# Безпека, Геоблокування та VPN
# Режими: "off" (вимкнено) | "cloudflare" | "nginx" | "standalone" (автономна перевірка)
GEO_RESTRICT_MODE=off
ALLOWED_COUNTRIES=UA
BLOCK_VPN=false

# Поштові сповіщення (SMTP)
# Залиште SMTP_HOST порожнім для логування листів у консоль
SMTP_HOST=
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=
SMTP_PASS=
SMTP_FROM=Система закупівель <noreply@procurement.local>
```

#### Приклад налаштування відправки через Gmail / Google Workspace:
```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=procurement@company.ua
SMTP_PASS=abcd efgh ijkl mnop
SMTP_FROM=Система закупівель <procurement@company.ua>
```
> **Як отримати пароль для Gmail:**
> 1. Увійдіть у Google Акаунт відправника (`myaccount.google.com`) та увімкніть **Двоетапну перевірку** (2-Step Verification).
> 2. Перейдіть у розділ **[Паролі додатків (App Passwords)](https://myaccount.google.com/apppasswords)**.
> 3. Введіть назву додатку (наприклад, `Procurement System`) та натисніть **Створити**.
> 4. Скопіюйте згенерований 16-значний код і вставте у `SMTP_PASS` (звичайний пароль від акаунта Google відхиляє з міркувань безпеки).

## 🛡️ 4. Архітектура та Безпека

* **Монолітний безпечний бекенд (Next.js):**
  Код доступу до бази даних, секретні ключі та бізнес-логіка позначені директивою `"server-only"` і виконуються виключно на сервері. Клієнтський браузер не має прямого доступу до БД.
* **Drizzle ORM:**
  Усі SQL-запити повністю параметризовані (Prepared Statements). Введення будь-яких спецсимволів чи лапок у пошук розцінюється рушієм як текст, що виключає SQL-ін'єкції.
* **Захист від сканування (`noindex`):**
  Сайт повністю закритий від пошукових роботів і сканерів на 3 рівнях: заголовок `X-Robots-Tag`, `robots.txt` (`Disallow: /`) та метатеги HTML.
* **Файлове сховище:**
  Завантажені зображення зберігаються поза каталогом `public/`. Доступ регулюється перевіркою прав до заявки чи картки номенклатури. MIME-тип визначається за сигнатурою файлу (Magic Bytes), а не за розширенням.

## 📋 5. Основні можливості системи

1. **Заявки на закупівлю:**
   * **Режими перегляду:** Канбан-дошка за замовчуванням та класична Таблиця (вибір автоматично запам'ятовується в cookies/localStorage).
   * **Наскрізний пошук:** швидкий пошук за номером, назвою товару, артикулом, кодом 1С/БАС та автором. Згортання фільтрів під кнопку з лічильником активних умов.
   * **Масовий вибір:** додавання позицій з довідника або «Моїх номенклатур» одразу з можливістю вказати кількість у модальному вікні.
   * **Створення на основі:** дублювання будь-якої заявки в один клік зі збереженням підрозділу, цеху та специфікації позицій.
   * **Редагування та воркфлоу:** покроковий життєвий цикл, повернення на доопрацювання (запит уточнення), розділення позицій у нову заявку.
   * **Друк:** офіційна друкована форма зі специфікацією (примітки перенесені акуратно під найменування).
2. **Номенклатура:**
   * Довідник товарів, контроль дублікатів (за назвою/артикулом), підтримка коду 1С/БАС, історія змін та об'єднання позицій.
   * Оновлений рядок швидкого пошуку та фільтри за статусом, джерелом («Мої номенклатури») та популярністю.
3. **Адміністрування:**
   * Керування користувачами та ролями з матрицею дозволів (RBAC).
   * Довідники напрямів, виробничих цехів та одиниць виміру (створення, редагування, деактивація).
   * Повний журнал аудиту всіх дій у системі.
   * Автоматична поштова розсилка HTML-сповіщень про створення заявок, зміну статусів та призначення відповідальних.
   * **Централізована мова інтерфейсу:** вибір мови за замовчуванням при розгортанні через `DEFAULT_LOCALE` у `.env`, а також динамічне перемикання мови всієї системи для всіх користувачів у *Адміністрування* → *Налаштування системи* → *Мова системи*.
